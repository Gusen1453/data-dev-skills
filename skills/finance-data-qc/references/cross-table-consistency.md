# 跨表一致性

单表全绿、跨表拼起来就错，是投研取数最常见的返工来源。分析师会把行情表、财务表、主数据表、实时表 join 在一起用，任何一处口径不齐都会直接进研究结论。

做法：先列**同义字段清单**（同一业务含义在各表的落地方式），再逐行核对下面七项。

| 核对项 | 查什么 | 判定 |
|---|---|---|
| 单位 | 同义字段的量级、小数位、是元/万元/百万、比率是小数还是百分数 | 用可复算关系确认，不能只看小数位 |
| 命名 | 同义字段是否同名同类型；同名字段是否真的同义 | 同名不同义比不同名更危险，优先排查 |
| 市场类型 | 市场、板块、上市地等枚举值的取值域是否跨表一致 | 取值域不一致时下游 join 会静默丢行 |
| 交易所 | 交易所字段的编码体系、是否可为空、"未知"如何表示 | 空值与"未知"混用会让筛选条件失效 |
| 币种 | 是否每张含金额的表都有币种字段，取值是否同一编码 | 币种缺失的表不能与含币种的表直接比金额 |
| 标的代码 | 代码体系、后缀规则、同一标的跨表能否一对一映射 | 需要映射表时，映射缺口就是数据缺口 |
| 库表名 | 测试库与生产库的库名、表名、字段名、前缀是否一致 | 不一致会导致测试通过、上线报错或取错表 |

## 时区

时区归到跨表一致性里查，因为它几乎只在跨表 join 时暴露。

- 逐表确认时间字段的存储时区，以及"业务日"如何定义。
- 用一个已知时点的同一事实，看两表时间戳是否相差固定小时数。
- 特别注意不同资产类别由不同链路接入时，一边存 UTC、一边存本地时间。
- 跨时区拼接前必须先统一到同一基准，再做日期对齐；否则边界日的数据会整体错位一天。

## 实时表与日频表

同一业务事实同时存在实时表和日终表时，逐项核对：

- **每标的每日一行**：实时表是否保证同一标的当日只有一行，不同交易状态放在同一行的不同列，而不是拆成多行。
- **字段齐备**：日频表有的关键字段（尤其币种、交易所、市场类型），实时表不能缺。
- **口径衔接**：收盘后实时表的值是否与日终表一致；不一致要能用快照时点解释。

## 复算优先

跨表一致性尽量用能形成闭环的关系确认，而不是靠比对字段名：

- 分钟数据在已确认会话和时区下重算日频，与日频表比对。
- 上游原始表与下游宽表按同一实体同一期比对具体值。
- 分项按维度求和与合计表对账。
- 明细金额与汇总金额在处理乘数、费用、舍入后对账。

任一输入口径仍是推断时，比对不成立只能记 `WATCH`。
