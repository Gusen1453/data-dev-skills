# 主动探索陌生 schema

## 先建立边界

1. **记录目标。** 写下用途、市场、标的类型、实体范围、时间范围、频率、预期使用者和需要回答的质量问题。
2. **声明预算。** 在执行前同时记录行数上限、执行时间上限、扫描字节或扫描量上限，以及 API 调用次数上限；数值由用户、平台限制或已批准任务提供，不在本 skill 中硬编码。
3. **预检代价。** 用 `EXPLAIN`、dry run、query profile、分区清单或引擎等价能力确认查询能裁剪分区/分片或命中索引。`LIMIT` 只限制返回量，不等于限制扫描量。
4. **限制查询。** 显式列出投影列、分区/时间谓词、实体谓词、稳定排序和结果上限。禁止无过滤条件、无结果上限的 `SELECT *`，禁止用 `ORDER BY random()` 在大表上抽样。
5. **保留余量。** 每轮结束记录实际消耗；预计下一轮会越过任一预算时降级或 STOP。

只读并不等于安全：即使账号无法写入，也不得发起无法估算扫描量的查询。

采样方法、统计项、逐步扩大规则与全表检查门槛见 `sampling-statistics.md`。该规程是执行要求，不是可选建议。

## 读取元数据

先读 catalog、schema、列名、类型、nullable、默认值、注释、主键/唯一约束、索引、分区和文件布局。把它们记录为 `OBSERVED`，但不要把列名或注释直接升级为业务事实。

从用途和结构中提出候选角色：

- 市场与标的：A 股、H 股、美股、指数、基金净值、外汇或其他未知市场。
- 时间：事件时间、交易日、分区时间、摄取时间、供应商发布时间或可得时间。
- 实体：证券、交易场所、报价源、币种、公司行动或日历。
- 数值：价格、数量、比例、金额、净值、因子或状态码。
- 时效与覆盖：更新频率、应到未到窗口、覆盖起点、最后可得时间。

每个候选角色都写 `依据`、`置信度`、`反证条件` 和需要补充的权威证据。未知市场前提时不套用其他市场的阈值或制度差异。

## 选择分层样本

按 `sampling-statistics.md` 的五阶段漏斗执行：元数据 → 小范围侦察 → 分层统计 → 异常下钻 → 有理由地扩大。不得跳过前四步直接跑全历史聚合。

在预算内至少覆盖会改变规则适用性的层次，不做单纯随机抽样：

- **按市场/标的：** 不同交易所、上市地、指数、基金、外汇对；若分类本身只是推断，先保留未知组。
- **按时间：** 最早/最晚边界、近期窗口、跨日/跨月边界、时区切换附近、已知公司行动日前后和供应商回补窗口。
- **按实体：** 不同币种、证券类型、流动性层级和数据覆盖长度。
- **按状态：** 正常交易、停牌、上市、退市、缺失、零成交量、公司行动和取消/修订状态。
- **按风险：** 数值极端、记录数最少、更新时间最旧、重复最多、未知或低频枚举值。

实体优先用稳定哈希分桶，时间序列使用连续窗口；不得用离散随机日期检查连续性。对大表先从元数据和分区统计开始，再对每层执行有投影、有谓词、有上限的查询。不能证明样本覆盖目标总体时，只报告已覆盖范围。

## 生成观察

按以下顺序逐步扩大查询，不一次扫描全部数据。每一步对应 `defect-catalog.md` 的一个缺陷族，具体手法去那里取：

1. **检查结构。** 比较类型、可空性、键候选、分区和时间粒度。
2. **检查分布。** 按字段角色选择统计：业务键看候选重复，时间键看桶计数与 gap，数值字段看极值与分位，枚举字段看 Top K 与低频值。不要对所有列机械执行同一组统计。
3. **检查缺失。** 按时间、实体和状态分组比较缺失模式，区分“不适用”和“未知”候选。
4. **检查重复。** 对候选复合键计数，并探索重复行是否来自版本、来源或更正。
5. **检查连续性。** 比较相邻观测与候选交易日历；自然停牌、休市和生命周期边界都可能反证“缺口”假设。
6. **检查跨字段关系。** 探索 OHLC、价格与数量、净值与份额、公司行动因子、币种单位、原始值与复权值之间可独立复算的关系。
7. **检查时效与覆盖。** 对照已确认或候选的更新制度，观察实时/T+1 延迟、应到未到与覆盖起点；制度未确认时只记观察，不下 PASS/BLOCK。

精确 distinct、高基数全量分组、无索引排序、全历史分位数和大表 join 都要单独预算。先用分区统计、近似值或候选检测缩小范围，再对异常层精确验证。

## 扩大查询的决策

每次扩大范围前回答：

1. 当前样本不能回答哪个问题？
2. 下一次只扩大实体、时间、分区还是精度中的哪一个？
3. 结果为 A 或 B 时分别如何改变结论或下一步？
4. 预计代价是否仍在预算内？

没有明确答案就不扩大。全表检查只有在精确总体结论不可替代、执行计划与扫描量已知、预算获批且能超时取消时才允许。历史已验且未变化的分区优先跳过，只检查新增分区、可回补窗口和发生版本变化的范围。

## 输出可证伪假设

每项输出使用同一结构：

```yaml
hypothesis_id: H-001
observed:
  evidence_level: OBSERVED
  statement: "有界查询实际得到的事实"
inferred:
  evidence_level: INFERRED
  statement: "候选语义或异常原因"
  basis: ["支持该推断的观察"]
  confidence: 中
  falsifier: "会推翻该推断的查询结果、规范或业务关系"
next_evidence: "升级到 CONFIRMED 所需的契约、用户确认或独立交叉验证"
decision: WATCH
```

高置信度 `INFERRED` 仍只能得到 `WATCH`。置信度用于安排下一步探索，不用于产生 PASS 或 BLOCK。

## 降级与 STOP

- **STOP：** 发现明文凭据、私钥或敏感令牌可能进入命令、日志或报告。
- **STOP：** 账号存在写权限且不能建立只读边界，或请求包含写操作。
- **STOP：** 查询无法限制列、时间、实体、分区或结果行数，形成无界扫描。
- **STOP：** 预算超限，或无法估算下一次查询的扫描量。
- **STOP：** 样本含未脱敏账户、持仓、交易或其他敏感数据。
- **STOP：** 数据形态不支持安全只读解析。
- **降级：** 缺少连接或只提供 schema 时，只生成查询计划和待验证假设。
- **降级：** 某一分层无法访问时，明确缩小数据范围并将相关结论保留为 WATCH。
