# 数仓结构审查

审查数据结构是否"良态"：分层清晰、粒度单、主键唯一、时态可信、契约不漂移、无重复逻辑。目标不是
让你推翻重建，而是定位结构病灶——改一处能救一堆查询。

## 这个 skill 交付什么

用户给一套表/数仓结构，你产出：

1. **结构审查报告** `structure-review.md`：按结构面逐条观察、证据等级、PASS/WATCH 结论。
2. **改进建议**：每条结构问题给"改哪、怎么改、影响谁"，不改代码——建议是可执行的描述。

审查只读：只用元数据与结构信息，不跑全量数据。

## 与通用 /solid /数仓规范的关系

- 通用 `/solid` 做**模块依赖方向/可测性**；**data-solid** 做**数仓结构五面**（下方）。
- 借鉴 solid 的原则：单一职责（一层一界？不，数据层按"粒度单 + 契约不漂移"解释）、依赖方向（下游不反向依赖上游产生的模糊口径）、开闭（新增口径不破坏既有表，用新表/新列而非改写历史）。
- 复用套件证据分级：`OBSERVED`（元数据/结构事实）、`INFERRED`（语义推断）、`CONFIRMED`（契约确认）；结论只 `PASS`/`WATCH`（结构审查不轻易 BLOCK，改表是执行器责任）。

## 五个结构面（一次审查一个，按序）

| # | 结构面 | 审查什么 | 病灶信号 |
|---|---|---|---|
| 1 | 分层完整性 | ODS/DWD/DWS/ADS 是否成链，有无跳层/裸用贴源 | 报表直查 ods、无 dwd 明细沉淀 |
| 2 | 粒度与主键 | 每表粒度是否单一、主键是否唯一且覆盖分区 | 一张表混日/分钟粒度、主键缺分区列导致重复 |
| 3 | 时态/PIT | 事件/可得/摄取是否分列、可用时点可重建 | end_date 与 ann_date 合并、改历史覆盖当时可见 |
| 4 | 契约一致性 | 字段与 contract.yaml 同名同义、单位/枚举/时区一致 | 同义字段跨表不同名、单位漂移（元 vs 万元） |
| 5 | 复用与重复 | 同口径是否集中定义、计算是否重复抄 | 毛利率/PE(TTM)公式抄 N 处、改一处漏一处 |

严格一次一面，按依赖序：分层 → 粒度 → 时态 → 契约 → 复用。先给结构面结论再下手条。

## 证据纪律

- **结构事实**（字段类型、主键、分区、注释）→ `OBSERVED`。
- **语义推断**（"这大概是复权因子"）→ `INFERRED`，标依据与反证条件。
- **契约确认**（contract.yaml / 规范有据）→ `CONFIRMED`。
- 只有 `CONFIRMED` 能定 `PASS`；命名/注释/单一分布线索只能 `WATCH`，不轻易 `BLOCK`——改表是执行器责任，data-solid 只给审查点。

## 审查流程

1. **点清对象**。用户给的表/库清单、用途、市场/实体范围。
2. **读结构**。元数据：表注释、列、类型、主键/唯一、分区、契约（contract.yaml 若有）。
3. **选面**。从五个面判断先审哪个（按依赖序，不跳）。
4. **给证据**。逐条观察标 OBSERVED，语义推断标 INFERRED + 依据 + 反证。
5. **定结论**。PASS/WATCH；未确认不 BLOCK。
6. **交付**。structure-review.md + 改进建议清单（改哪/怎么改/影响谁），不代跑建表。

## 改进建议模板

```yaml
issue_id: DWS-001
structure_surface: "契约一致性"
observed: "close_price 在 A 表带单位元、B 表是万元，命名相同"
evidence_level: OBSERVED
decision: WATCH
suggested: "统一到 contract.yaml 的 close_price 口径；单位差异改名 close_price_wan 或统一元"
impact: "下游估值/行情 join 会算错量级"
owner_executor: "finance-ddl-design（改表）"
```

## Red Flags

- 审一个结构面却扯到别的面（回到一次一面）
- 命名/注释线索直接 BLOCK（未确认只能 WATCH）
- 在审查阶段代跑执行器建表/改表
- 只给"代码"不给"改哪/影响谁"
- 不标证据等级

## Checklist

- [ ] 五个面按依赖序一次一面
- [ ] 结构事实 OBSERVED、语义 INFERRED、契约 CONFIRMED
- [ ] 结论 PASS/WATCH，无确认不 BLOCK
- [ ] 建议含改哪/怎么改/影响谁
- [ ] 只审查，改表交给执行器
