# 幂等

投研管道的默认要求：**同参数重复执行，结果一致**。任何任务都可能重跑——手动误触发、失败重试、回补重放——没有幂等，一次重跑就制造重复或覆盖。

## 定义与验收

- 幂等 = 对同一输入窗口执行 N 次，目标表最终态与执行 1 次一致。
- 验收方式：同一窗口跑两遍，比对行数、主键唯一性与关键金额；对不上就是非幂等。

## 手段（按适用场景选）

| 手段 | 适用 | 实现 | 注意 |
|---|---|---|---|
| 分区原子替换 | 目标按时间分区、当日全量可重算 | `INSERT OVERWRITE PARTITION` / 同事务 `TRUNCATE+INSERT` | 覆盖窗口必须等于增量窗口；覆盖期间读不到半态 |
| 键去重 | 目标有业务唯一键 | 写入前按键去重，或表上唯一约束 + `INSERT IGNORE`/去重查询 | 去重键 = 业务唯一键，来自 DDL 契约 |
| Upsert | 修订/晚到要覆盖同键旧值 | `MERGE` / `ON CONFLICT` / `ON DUPLICATE KEY UPDATE` | 覆盖语义要写明：全字段覆盖还是仅指定列 |
| 先删窗口再插 | 目标无覆盖语法 | 删除与插入同一事务 | 删除与插入不在同一事务 = 失败半态 |

## 判定清单

1. **目标键是什么？** 来自 `contract.yaml` 的 `keys`；未声明主键的表，先回 DDL 责任确认键，否则去重无锚点。
2. **失败中间态**：写了一半失败，重跑后会不会残留半批？分区替换/同事务删除+插入能避免，逐行 upsert 不能。
3. **同窗口全量重跑**：结果是否与首次一致？键去重与 upsert 都要过这一关。
4. **版本列参与去重**：修订场景去重键 = (业务键, 可得时间/版本)，否则旧版本被新版本顶掉或重复。
5. **跨分区**：增量窗口跨两个分区（晚到数据进前一日分区）时，两个分区都要原子处理。

## 反例

- 逐行 `INSERT` 无去重：重跑一次，同一天出现两行。
- `TRUNCATE` 与 `INSERT` 分两次执行：中途失败表是空的。
- 去重键漏了 `data_src`：两供应商同键互相覆盖。
- 用"先查有没有再插"代替幂等：并发下依然重复（TOCTOU）。
