# 出参规范：字段、单位、空值口径

出参是 LLM 直接读的：字段名歧义会让模型说错话，空值不分类会让模型编造。规范目标：**可读、无歧义、诚实**。

## 字段命名

1. 与 DDL 契约（`contract.yaml` 的 `schema`）同名同义；禁止发明同义名（`close` vs `close_price`）。
2. 每个字段在契约里声明：类型、单位、枚举取值、空值口径。
3. 出参给中文可读名（`field_label`）与稳定字段名（`field`）双轨：模型读 label 说人话，下游程序用 field 解析。

## 单位与量级

- **结构化字段保持原始单位**：价格 `元`、数量 `股`、金额 `元`、比率 `%`（明确是百分数还是小数）。单位来自 DDL 契约，不重新定义。
- 数值与单位同出：`{"field":"close_price","value":7.25,"unit":"元"}`，或字段名自带单位后缀（`close_price_cny`）二选一，全接口统一。
- **量级换算只出现在可读化转写层**：`123456789` 元 → "约 1.23 亿元"；结构化字段不换算，防止程序解析错量级。
- 货币：跨市场出 `currency`（`CNY`/`HKD`/`USD`）；单市场在接口级声明币种。

## 空值分口径（核心）

禁止裸 `null` 混用。每个缺失值必须有明确的 `absence_reason` 与中文诠释：

| 口径 | 代码 | 含义 | 出参示例 |
|---|---|---|---|
| 未查到 | `NOT_FOUND` | 标的代码/名称不存在，或已退市且无历史 | `{"absence_reason":"NOT_FOUND","message":"未查到该标的"}` |
| 数据暂无 | `NO_DATA` | 标的存在，该时间点无数据（未上市、尚未披露） | `"数据暂无（尚未披露）"` |
| 非交易日 | `NON_TRADING` | 该市场该日休市 | `"非交易日（香港公众假期休市）"` |
| 不适用 | `NOT_APPLICABLE` | 字段对该标的不适用（如银行股无某衍生字段、指数无成交量） | `"不适用（指数无成交量指标）"` |
| 未知 | `NULL` | 应有值但缺失，无口径说明 | `"未知（上游缺失，待确认口径）"` |

规则：

- 每个口径给 `code` + `message`（中文一句话），LLM 直接引用 message 即可。
- 同一字段不同标的/不同时间的缺失可能是不同口径：按行标注，不按接口统一。
- 诚实语义：**不填充、不猜测、不把"暂无"当 0 或 -1**。`0` 只表示真实的零值（如成交量 0 与停牌是两回事）。
- **空数组落地形态**：数据块为数组时，"标的存在但暂无数据"用空数组（`items: []`），与消歧无命中（`NOT_FOUND`，无标准化信息）严格区分。三级语义：消歧无结果 → 有标准化信息但数据空 → 有数据。

## 模块化出参（实测归纳）

给 LLM 用的查询接口出参按模块分区，每个模块职责单一，调用方按需取：

1. **按原输入键控**：批量查询的 `data` 键 = 用户原输入字符串，值与输入一一对应（`{"贵州茅台": {...}, "sz300033": {...}}`）。LLM 免维护"传了什么↔返回了什么"的映射。
2. **消歧内嵌块**：每个输入下先出"标准化信息块"（标准化代码、名称、市场/交易所），数据块紧随其后——查询接口封装消歧 top-1 的落地形态（见 `disambiguation.md`）。
3. **数据数组化**：同主体多期/多条数据用数组（一期一条）；空数组语义见上。
4. **分页元数据块**：筛选/分页类接口独立一块（total、page、size、totalPages），不混进结果行。
5. **条件回显块**：筛选接口回显每个筛选条件——中文描述、格式化后的条件原文、命中数；枚举条件细分到每个取值 + 合计。价值：LLM 能评估"这轮筛选严不严"，回答"为什么只剩这些"。
6. **原始值/展示值双轨**：结构化字段给程序用（数值全精度、原始单位），展示字段给 LLM/人读（千分位、量级换算、取整），命名用 `*Display` 后缀区分；两轨同出，互不覆盖。
7. **数值可读化**：大金额可用千分位字符串（一眼看出量级），比率用百分数（显式声明是百分数还是小数）；代价是程序解析要处理逗号——取舍写入契约。
8. **代码三元组**：代码相关字段跨接口统一（裸代码 / 市场前缀全小写代码 / 名称），与消歧服务的标准化输出同构；市场前缀代码是跨接口稳定键。

**反模式（写契约时规避，也是质检"接口层/注释口径"可抓的点）**：字段名与语义不符（如"发布日期"实为报告期）、冗余同值字段并存、同一协议字段跨接口类型不一致（如 code 一处字符串一处数字）、单位隐含不声明。

## 枚举与布尔的中文诠释

- 出参枚举给 `value`（稳定码）与 `label`（中文）：`{"value":"listed","label":"正常上市"}`。
- 布尔：`is_trading` → `true/false` 之外给 label（`正常交易`/`停牌`），避免模型把 `false` 说成"没有交易"。

## 标的字段

- 标的代码用消歧服务返回的标准化代码（全接口统一格式）；同出 `name`（标准名称）与 `matched_input`（用户原输入，便于追溯）。
- 消歧无命中 → 空值口径 `NOT_FOUND`（"未查到该标的"）；不做候选与置信度输出，匹配正确性由消歧服务负责（见 `disambiguation.md`）。

## 数据时效声明

- 出参带 `as_of`（数据截至时间）与 `source`（数据源版本）：模型能回答"这是什么时候的数据"。
- 缓存接口声明 `cached_at`；超过时效的缓存要能识别。

## 反例

- `{"close": 7.25}`：单位不明（元还是美元？）、字段名与契约不一致。
- `{"amount": null}`：是没查到、没披露还是不适用？模型只能猜。
- 用 `0` 表示停牌日成交：模型会答"成交 0 股"，其实是非交易日/停牌。
- 出参不带 `as_of`：模型把 3 天前的数据说成"最新"。
