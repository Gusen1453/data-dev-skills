# 查询面、入参与分页性能

接口是给 AI LLM 工具用的：模型靠入参描述决定怎么调，靠出参决定怎么说。入参每多一个维度，模型选错参数的概率就高一分。

## 查询面：一个接口一个定位

按消费场景拆接口，不做一个"万能查询"：

| 场景 | 接口定位 | 典型主参 |
|---|---|---|
| 单标的单日 | 问"XX 今天收盘多少" | 标的、日期 |
| 单标的区间 | 问"XX 近一个月走势" | 标的、from/to |
| 多标的对比 | 问"A 和 B 谁的估值低" | 标的数组、日期/字段 |
| 批量最新值 | 问"持仓 50 只今天的涨跌" | 标的数组（≤上限） |
| 最新/快照 | 问"XX 最新净值" | 标的 |

查询定位写进契约的 `query_id` 与 `purpose`，禁止用同一接口的参数组合模拟不同定位。

## 入参设计（LLM tool 友好）

1. **主参 ≤ 4 个。** 标的、时间范围、字段集（可选）、分页（可选）。更多需求走高频筛选，仍不够就换接口。
2. **标的参数形态**：允许不标准输入——标准代码、裸代码、市场前缀代码、名称、别名、大小写与拼写变体都接受；接口内部调用现有消歧服务批量标准化（见 `disambiguation.md`），不要求调用方先查代码再查数据——那是把复杂度推给模型。
3. **时间范围**：`from`/`to` 两个标量日期，不嵌套区间对象；默认值语义明确（如"默认最近 20 个交易日"），写入契约。
4. **字段集**：可选，白名单来自契约 `schema`；不传返回默认字段集。
5. **禁止**：嵌套对象参数、枚举魔法数、多级筛选组合（`filter[status][eq]=x` 这种）、要求调用方拼复杂表达式。
6. **批量上限**：标的数组上限（如 50）写进契约；超限返回明确错误"最多 50 个标的"，不静默截断。

## 筛选：只留高频

- 只保留调用方真正会用的筛选（如 `list_status`、`market`）；低频筛选不进接口。
- 筛选取值用可读枚举（`"listed"`/`"delisted"`），不暴露底层 magic number。
- **筛选入参模块化**（参考实测形态，字段名通用化）：分页（page/size）+ 排序数组（field + order）+ 数值条件数组（key + range.gte/lte）+ 枚举条件数组（key + values）。数值条件与枚举条件分开成组，每组一个条件一个键；条件键与出参字段同名，便于对账。出参侧配套条件回显（见 `output-semantics.md` 模块化出参）。

## 分页与性能

- **分页**：`page`（从 1 起）/`page_size`（上限如 1000）；返回 `total` 与 `has_more`；默认第一页。
- **批量查询**：小批量（≤ 上限）默认一次全量返回，不强制分页；大批量才分页。
- **超时与扫描预算**：每个接口写超时上限与扫描预算（行数/分区），来源是 DDL 契约的分区键；示例查询必须能裁剪分区（时间范围必填或默认有界）。
- **缓存策略**（可选）：写进契约；必须声明缓存刷新时点，避免"接口返回的净值是昨天的"。

## 反例

- 入参 `filters: [{field:"status", op:"eq", value:1}]`：模型大概率拼错。
- 不设批量上限：模型传 500 个代码，接口跑 10 分钟超时。
- 时间范围缺省为"全部历史"：每次调用扫全表。
