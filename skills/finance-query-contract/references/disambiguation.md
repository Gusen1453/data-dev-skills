# 标的消歧与标准化代码

调用方（尤其是 LLM）给的标的五花八门："茅台"、"浦发"、"bj920799"、"003816.SZ"、"GOOG"、"BRK"。**消歧已有现成的内部服务**（批量查询场景：一组 queries 逐条返回 top-1 标准化代码）。查询接口的职责只有一个：**把不标准输入换成标准化代码，然后用它查数据**。

## 职责边界

- **消歧服务负责**：匹配正确性、模糊匹配、多市场同名、top-1 是否与用户意图一致。匹配错了，是消歧任务要去解决的问题。
- **查询接口负责**：允许不标准输入 → 调用消歧服务取 top-1 → 用返回的标准化代码作为查询键 → 查数据 → 输出。
- **查询接口不负责**：不做候选列表、不传播置信度、不替用户判断歧义、不重复实现市场推断。越权做这些，只是把消歧的活搬进查询接口，制造两套口径。

## 允许不标准输入

| 输入形态 | 示例 |
|---|---|
| 标准代码 | `600519.XSHG`、`00700.HK`、`AAPL.US` |
| 裸代码 | `600519`、`00700`、`BRK` |
| 市场前缀小写代码 | `sz300680`、`bj920799`、`usGOOG` |
| 名称 / 别名 | `茅台`、`浦发`、`中国平安` |
| 大小写与拼写变体 | `google`、`GOOGL`、`spacex` |

## 封装协议

1. 把入参标的批量发给消歧服务（batch 场景）。
2. 逐条取回 top-1：标准化代码（含中英文名、市场/交易所、标的类型）。
3. 把标准化代码作为查询键查数据。
4. 出参统一用消歧服务返回的标准化代码格式（全接口一致；内部字段映射写进 `api-spec.md`，含内部信息的映射不进公开仓库）。
5. **消歧服务未返回结果** → 空值口径 `NOT_FOUND`（"未查到该标的"），不猜、不编造代码。

## 反例

- 查询接口返回候选列表、让 LLM 追问"你要哪一个"：越权，消歧的活不该在这里干。
- 查询接口透传置信度、fuzzy 提示让 LLM 判断：同上，匹配可信度是消歧服务的输出，不是查询接口的裁决点。
- 在查询接口里重复实现市场推断规则：消歧服务已归一化输入（`.SZ`→`XSHE`、`bj` 前缀等），重复实现只会制造两套口径。
- 把消歧逻辑写成文档让调用方自己拼代码：复杂度被推给 LLM，违背入参简单原则。
