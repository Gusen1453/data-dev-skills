# 标的消歧与标准化代码

调用方（尤其是 LLM）给的标的五花八门："浦发银行"、"浦发"、"600000"、"600000.SH"、"SH600000"。接口内部完成消歧，出参统一标准化代码。**消歧是接口的责任，不是调用方的。**

## 输入接受形态

| 形态 | 示例 | 处理 |
|---|---|---|
| 标准代码 | `600000.SH`、`00700.HK`、`AAPL.US` | 直接匹配 |
| 裸代码 | `600000`、`00700` | 按市场规则推断（见下），二义性时返回候选 |
| 名称 | `浦发银行` | 精确匹配 → 别名匹配 → 模糊候选 |
| 别名 | `浦发`、`中国平安A` | 别名表匹配；失败给 Top N 候选 |

## 市场推断规则（A/H/美股等）

- 6 开头 6 位数字 → 上交所（`.SH`）；0/3 开头 6 位 → 深交所（`.SZ`）；4/8 开头 → 北交所（`.BJ`）。
- 5 位数字开头 0 → 港股（`.HK`）。
- 字母/含点 ticker → 美股（`.US`，如 `BRK.B`）。
- 推断规则只用于"给出候选"，不用于"直接确定"：`600000` 在 A 股唯一 → 可确定；`00700` 只有港股 → 可确定；`955` 之类无法推断 → 返回候选。

## 消歧策略（按顺序）

1. **标准化代码精确匹配** → 直接返回。
2. **裸代码 + 唯一市场推断** → 返回标准化代码，标注推断依据（`matched_via: "market_rule"`）。
3. **名称精确/别名匹配** → 返回标准化代码。
4. **多市场同名**（如 A/H 同名公司）→ 返回候选列表 + `ambiguous: true`，不擅自选市场。
5. **模糊匹配** → 返回 Top N 候选（含代码、名称、市场），不猜。

## 统一输出

- 出参中标的代码一律 `MARKET.CODE` 形式：`600000.SH`、`00700.HK`、`AAPL.US`。
- 出参同时给 `name`（标准名称）与 `code`（标准化代码）；有别名命中时返回 `matched_input` 便于追溯。
- **失效标的**（退市）：仍可查历史数据，`list_status: "delisted"` 标注；已退市且无历史 → 走空值口径 `NOT_FOUND`（见 `output-semantics.md`）。

## 反例

- 入参 `600000` 直接按沪市确定——万一用户想要的是港股同名代码，错得悄无声息；正确做法是标注推断依据或返回候选。
- 名称匹配不区分 A/H：`中国平安` 该返回哪个市场？必须返回候选。
- 把消歧逻辑写在文档里让调用方自己拼代码：复杂度被推给 LLM，违背入参简单原则。
