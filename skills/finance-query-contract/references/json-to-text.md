# 可读化转写：json → str

接口结构化返回（json）给程序用，但给 LLM 消费时，一段组织好的话比 json 更好：**可读性强、逻辑清晰、token 更少**（省掉键名、括号、引号）。每个查询接口必须配套一个 json→str 转写方法，转写规则写进契约。

## 转写规则

1. **主谓宾句式**：`<名称>（<标准化代码>）<时间> <字段> <值> <单位>`。
   - 例："浦发银行（600000.SH）2024-01-15 收盘价 7.25 元。"
2. **空值按口径转写**：用 `output-semantics.md` 的 message 原话。
   - `NOT_FOUND` → "未查到该标的"；`NO_DATA` → "数据暂无（尚未披露）"；`NON_TRADING` → "非交易日（休市）"；`NOT_APPLICABLE` → "不适用（原因）"。
   - 空值**不省略关键事实**：如果整行只有空值，要说"该日无数据"，不能说成"该日没有发生交易"。
3. **单位带进句子**：`7.25 元`、`涨跌幅 +1.2%`，裸数字必须带单位。
4. **量级换算并标注"约"**：`123456789 元` → "成交额约 1.23 亿元"；换算出现在转写层，结构化字段保持原始单位。
5. **枚举转中文**：`is_trading=true` → "正常交易"；`list_status="listed"` → "正常上市"。
6. **批量分组**：按标的或时间组织；总条数说清楚（"共 5 条"）；同标的连续日期合并成区间描述（"1 月 10 日至 1 月 14 日连续上涨"）而非逐日罗列。
7. **数据时效**：句首或句尾一句"数据截至 <as_of>，来源 <source>"。
8. **不丢关键事实**：代码、时间、数值精度、口径必须保留；转写后要能无损映射回结构化字段。
9. **单位统一**：一段话内同一单位写法一致；跨币种标币种。

## 对照示例

**入参**：查询浦发银行 2024-01-15 行情。

**json 出参**（92 tokens 左右）：

```json
{
  "query_id": "quote_daily",
  "data": {
    "code": "600000.SH",
    "name": "浦发银行",
    "trade_date": "2024-01-15",
    "close_price": {"value": 7.25, "unit": "元"},
    "chg_rate": {"value": 1.2, "unit": "%"},
    "turnover_amt": {"value": 123456789, "unit": "元"},
    "is_trading": true
  },
  "as_of": "2024-01-15T18:00:00+08:00",
  "source": "vendor_x v2.1"
}
```

**json→str 转写**（约 55 tokens）：

> 浦发银行（600000.SH）2024-01-15 收盘价 7.25 元，涨跌幅 +1.2%，成交额约 1.23 亿元，正常交易。数据截至 2024-01-15 18:00，来源 vendor_x v2.1。

**批量+空值示例**（转写）：

> 共 3 条：浦发银行（600000.SH）1 月 15 日收盘 7.25 元；建设银行（601939.SH）该日数据暂无（尚未披露）；汇丰控股（00005.HK）非交易日（香港公众假期休市）。数据截至 1 月 16 日 09:00。

## 转写的取舍

- 转写**不是**丢弃结构化：字段仍按契约顺序组织，数值精度不截断（`7.25` 不写 `7`）。
- 同一事实给两种表达的地方（字段名+label）转写时只留 label，省 token。
- 时间区间合并只用于连续同状态序列；跳变点必须单独列出，防止"连续上涨"掩盖中间某天下跌。
- 句长控制：一条事实一句，逗号连接同主体事实；不同标的/不同日期另起句。

## 反例

- `"close_price":7.25` 直接转写为"收盘价 7.25"：单位丢了。
- `"amount":null` 转写为"成交额 0 元"：把缺失说成零。
- 批量 50 条逐条转写：token 反而比 json 多；正确做法是分组、区间合并、只展开异常项。
- 转写后丢了 `code`：模型无法再发起后续查询。
