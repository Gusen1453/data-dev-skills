# 正反例

## 正例 1：单标的行情查询接口

**需求**：AI 工具要能回答"XX 今天收盘多少"。数据源 `dwd_cn_stock_daily_bar`（DDL 契约：`close_price` 单位元、`chg_rate` 百分数、`turnover_amt` 单位元）。

**入参**：`instruments`（代码/名称/别名，≤50）、`trade_date`（必填）、`fields`（可选）。

**出参**（结构化）：

```json
{
  "query_id": "quote_daily",
  "data": {
    "code": "600000.SH",
    "name": "浦发银行",
    "trade_date": "2024-01-15",
    "close_price": {"value": 7.25, "unit": "元"},
    "chg_rate": {"value": 1.2, "unit": "%"},
    "turnover_amt": {"value": 123456789, "unit": "元"},
    "is_trading": {"value": true, "label": "正常交易"}
  },
  "as_of": "2024-01-15T18:00:00+08:00",
  "source": "vendor_x v2.1"
}
```

**json→str**：

> 浦发银行（600000.SH）2024-01-15 收盘价 7.25 元，涨跌幅 +1.2%，成交额约 1.23 亿元，正常交易。数据截至 2024-01-15 18:00，来源 vendor_x v2.1。

**要点**：入参 3 个、消歧内部完成、字段带单位、布尔带 label、转写保留代码/精度/时效，token 明显少于 json。

## 正例 2：批量查询 + 空值分口径

**入参**：`instruments: ["浦发银行","建设银行","00005.HK"]`，`trade_date: "2024-01-15"`。

**出参转写**：

> 共 3 条：浦发银行（600000.SH）收盘 7.25 元；建设银行（601939.SH）数据暂无（尚未披露）；汇丰控股（00005.HK）非交易日（香港公众假期休市）。数据截至 2024-01-16 09:00。

**要点**：同一日期三种标的三种口径，逐行标注；`00005.HK` 裸代码被正确推断为港股；不把"暂无"和"休市"混为一谈。

## 反例 1：入参堆复杂度

```json
{"symbols": [{"type": "stock", "code": "600000", "market": "SH"}],
 "time": {"start": "2024-01-01", "end": "2024-01-15", "tz": "Asia/Shanghai"},
 "filter": [{"field": "status", "op": "eq", "value": 1}]}
```

**问题**：嵌套对象 + 枚举魔法数 + 筛选组合，模型选错概率高；违背入参简单原则。正确做法：`instruments`、`from`/`to` 平铺标量。

## 反例 2：裸 null 与单位缺失

```json
{"code": "600000.SH", "trade_date": "2024-01-15",
 "close_price": 7.25, "amount": null, "is_trading": 0}
```

**问题**：`amount` 裸 null（没查到？没披露？休市？）；`close_price` 无单位；`is_trading: 0` 模型会答成"没有交易"。正确做法：字段带单位、空值带 `absence_reason` + message、布尔带 label。

## 反例 3：消歧失败硬猜

**入参** `instruments: ["中国平安"]`，接口直接返回 A 股 `601318.SH` 而不返回候选。

**问题**：中国平安 A/H 同名，用户可能想要 `02318.HK`；硬猜让错误静默发生。正确做法：返回候选列表 + `ambiguous: true`。

## 反例 4：转写丢关键信息

> 收盘价 7.25 元，涨 1.2%，成交 1.2 亿。

**问题**：丢了代码、日期、精度（`1.2` vs `1.23`）、数据时效；模型无法继续追问、无法判断新旧。正确做法：保留代码/时间/精度/时效（见正例 1）。
