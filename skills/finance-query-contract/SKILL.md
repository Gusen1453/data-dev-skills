# 金融投研查询接口设计

服务券商与基金的分析师、研究员和给他们供数的人。接口主要消费方是 **AI LLM 工具** 与分析师。默认假设：**现有接口字段名靠猜、空值语义混乱、没有查询契约**。任务顺序：摸数据源 → 定查询面 → 定入参 → 定消歧 → 定出参 → 定转写 → 定分页性能 → 交付。

## 这个 skill 交付什么

用户给查询需求（或一个待审查的接口），你产出四样东西：

1. **接口契约** `api-contract.yaml`：每个查询的入参、出参 schema、语义、分页/批量上限、单位、空值口径。
2. **接口规格** `api-spec.md`：设计说明、消歧规则、标准化代码规则、可读化转写规则。
3. **示例** `examples/`：入参/出参示例，含 json 与 json→str 转写对照。
4. **排障报告**（排障场景）：根因定位、证据等级、修复建议。

接口契约与规格是交付物；设计依据必须可追溯到数据源契约。

## 六条核心原则（写任何接口前先对齐）

1. **入参简单。** 主参 ≤ 4 个（标的、时间范围、字段集、分页）；不引入嵌套对象、复杂筛选组合、枚举魔法数。
2. **支持分页/筛选/查询/批量查询。** 批量有明确上限；筛选只保留高频维度。
3. **字段名无歧义、可读，查询定位清晰。** 字段名与 DDL 契约一致，不发明同义名。
4. **内部封装消歧。** 允许不标准输入（名称/别名/大小写/拼写变体/市场前缀代码），接口内部调用现有消歧服务取 **top-1** 标准化代码作为查询键；匹配正确性由消歧服务负责，查询接口不做候选、置信度与歧义判断。
5. **输出诚实。** 单位与量级显式；空值分口径（未查到/数据暂无/非交易/不适用/未知），禁止裸 null 混用。
6. **可读化转写。** 提供 json→str 转写方法：一段话、可读性强、逻辑清晰、token 比 json 少。

## 硬性规范

1. **审查只读。** 设计/排障阶段只用只读访问；不直接部署或修改生产接口，除非用户明确批准。
2. **入参克制。** 入参不引入超过必要限度的复杂度；要复杂组合查询的用户引导走 SQL/数仓流程，不在接口层堆参数。
3. **空值必须有口径。** 未查到/数据暂无/非交易/不适用/未知分列输出，禁止裸 null 混用、禁止用 0 或 -1 冒充空值。
4. **字段语义一致。** 出参字段与 DDL 契约同名同义；单位、枚举、时区与契约一致。
5. **单位与量级显式。** 结构化字段保持原始单位（元/股/%）；量级换算（万/亿）只出现在可读化转写层并标注"约"。
6. **消歧无命中诚实告知。** 消歧服务未返回结果时输出空值口径 `NOT_FOUND`（"未查到该标的"），不猜、不编造代码；匹配错误不属查询接口职责。
7. **预算入契。** 分页上限、批量上限、超时与扫描预算写进契约；示例查询限定范围。
8. **证据分级。** 设计依据标 `OBSERVED`/`INFERRED`/`CONFIRMED`；字段口径只有契约或用户确认才能写进 api-contract.yaml。

## 执行流程

1. **确认边界。** 记录数据源表、消费方、调用方式、交付物、是否允许部署。
2. **摸数据源。** 读 DDL 产出的 `contract.yaml`（字段语义/键/时态）、目标表结构、现有接口与调用方。
3. **定查询面。** 按消费场景列出查询：单标的单日、单标的区间、多标的对比、批量最新值等；一个接口一个定位。
4. **定入参。** 主参（标的、时间范围、字段集、分页）+ 高频筛选；写明默认值语义与批量上限。
5. **定消歧。** 封装现有消歧服务（批量查询取 top-1），把返回的标准化代码作为查询键；无命中 → `NOT_FOUND`；不做候选、置信度与歧义判断（见 `disambiguation.md`）。
6. **定出参。** 按 `output-semantics.md` 定字段、单位、量级、空值分口径与枚举诠释。
7. **定转写。** 按 `json-to-text.md` 定 json→str 规则，产出对照示例。
8. **定分页与性能。** page/page_size 上限、批量上限、超时与扫描预算。
9. **交付。** 产出 `api-contract.yaml`、`api-spec.md`、示例；与 QC 接口层缺陷衔接（见 `contract-deliverables.md`）。

正反例见 `examples/few-shots.md`。

## 交付物要求

- **接口契约** `api-contract.yaml`：每个查询的 `query_id`、入参（名称/类型/必填/默认/上限）、出参 schema（字段/类型/单位/空值口径/枚举值）、分页与性能预算、数据时效声明。
- **接口规格** `api-spec.md`：查询面与定位、消歧规则、标准化代码规则、转写规则、与数据源契约的映射、待确认清单。
- **示例** `examples/`：每类查询一个入参/出参示例；出参同时给 json 与 json→str 转写两版。
- **排障报告**（排障场景）：根因假设的证据等级、反证条件、修复建议；未确认根因不写结论。

## 必须停下的情况

- 连接信息里有明文口令、私钥或会被写进交付物的令牌。
- 只有写权限账号可用，无法建立只读审查边界。
- 任务要求直接在生产部署或修改接口，未获用户明确批准。
- 无法确认数据源结构，写不出可验证的出参 schema。
- 空值口径与单位无法确认，却要求写死进契约。
- 示例查询无法限定范围，可能形成无界扫描。
- 需求实质是建表、管道、质检、治理或合规的最终结论：保存观察，回到 `using-data-dev` 选对应责任。
