# 数据开发设计先行

在数据开发动手前，先让用户和你对同一件事说出一致的话：做什么、边界在哪、关键决策怎么选。**设计没确认，不写 DDL、不建管道、不定义接口。**

## 这个 skill 交付什么

用户有数据开发需求但还含糊，你通过一次一问收敛出：

1. **设计决策记录** `design-decisions.md`：范围、期望结果、已敲定的关键决策（含选项字母标记）。
2. **衔接指引**：明确下一步该进哪个执行器（建表→finance-ddl-design、管道→finance-pipeline-dev、接口→finance-query-contract、质检→finance-data-qc）。

决策记录是后续执行器的**输入前提**，不重复生成 formal 交付物。

## 与通用 /grill 的区别

- 通用 `/grill` 解决"做什么产品/何时做"；**data-grill** 解决"数据怎么设计"——表的粒度/主键/时态、管道增量方式、接口入参边界、质检验收口径。
- 决策面换成数据开发术语；证据从库的元数据/契约查证（不靠猜），决策给你（不替用户定）。
- 一次一问、A/B/C/D 带 `Recommended:`、未确认不改码，这三个铁律原样保留。

## 核心原则（数据版铁律）

1. **一次一问。** 从不一次抛多个问题；先问会改变后面决策的那个。
2. **带推荐。** 每个多选必标 `A) Recommended: 机制—产出感`，给一个明确推荐并说明理由。
3. **证据查证。** 能查的（表要不要建、已有契约、库内惯例）从环境查，不问你；只有决策才问你。
4. **未确认不动手。** 设计没敲定，不写 DDL/脚本/接口契约/检查。
5. **不重造交付物。** 决策记录只记"已定/未定/待查"，formal 契约由执行器产出。

## 决策面（数据开发特有，一次揭一层）

按依赖顺序进：

| # | 决策面 | 典型问题 | 落到哪个执行器 |
|---|---|---|---|
| 1 | 范围与主交付物 | 要建表/管道/接口/质检？交给哪个执行器? | 先定这个，再下去 |
| 2 | 表设计 | 粒度（日/分钟）、主键、时态列（事件/可得/摄取） | finance-ddl-design |
| 3 | 增量与幂等 | 更新制度、增量方式（水位线/CDC/分区）、晚到容忍 | finance-pipeline-dev |
| 4 | 查询接口 | 查询面、入参、消歧 top-1、空值口径 | finance-query-contract |
| 5 | 验收口径 | 哪些缺陷族、证据等级、PASS/BLOCK 判据 | finance-data-qc |

严格按序，先回答范围，再逐步下沉；前面的答案会改后面的问题。

## Grill loop（数据版）

对每个节点：

1. **查证**：是"环境里有什么"（现有表、契约、库内惯例）→ 查，不问。
2. **决策**：是"怎么设计"的用户决策 → 恰好问一个。
3. 多选用 A/B/C/D，标 `Recommended:`，选项同时给出「机制 + 产出感」。
4. 等答案再往下一个。
5. 挑战含糊假设：需求说"建张行情表"却没提粒度 → 追问粒度，不默认。

直到你能把设计总结成几句用户认可的要点（数据产出 + 背后的表/增量/契约机制）。

## 决策记录模板

```markdown
# 数据设计决策记录
## 范围
- 主交付物：<建表/管道/接口/质检/其中几个>
- 数据集/表：<目标表或数据集>
## 期望结果
- <用户要的最终产出，人话>
## 已敲定决策
- <决策面>：选了 <选项字母 + 机制>，因为 <一句话理由>
## 待查 / 待确认
- <未敲定的，留给执行器>
## 下一步
- 进 <finance-xxx>：<该执行器要接的输入前提>
```

## 硬门 → 执行器

设计确认后：**不要自己动手写 DDL/脚本**；把决策记录交给对应执行器执行。它才是产出正式交付物（contract.yaml / pipeline.yaml / api-contract.yaml / 质检）的负责方。data-grill 停在"设计已敲定"。

## Red Flags

- 一次抛多个问题（回到铁律 1）
- 选项无 A/B/C/D 字母标记、无 `Recommended:`
- 选项只给机制不给产出感，或反之
- 在用户确认前写了 DDL/脚本/接口契约
- 问用户"库里有什么"这种能自己查证的事实
- 生成 contract.yaml 等执行器才该产的正式交付物

## Checklist

- [ ] 范围决策先定，再下沉细节
- [ ] 一次一问；证据查证；决策给你
- [ ] 每个 A/B/C/D 带 `Recommended:`
- [ ] 产出轻量决策记录，不重造契约
- [ ] 交由执行器接续，data-grill 停在设计确认
