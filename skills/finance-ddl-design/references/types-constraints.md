# 类型、约束与注释

类型选错是投研数据的常见事故源：float 存价格导致复算对不上、日期存字符串导致排序错、代码存整数丢前导零。本节给出裁决规则；库内惯例冲突时先按 `exploration.md` 裁决。

## 类型选择

| 数据角色 | 推荐类型 | 禁止/慎用 | 理由 |
|---|---|---|---|
| 金额、价格、净值 | `DECIMAL(p,s)`（如 `DECIMAL(20,4)`） | `FLOAT`/`DOUBLE`、`REAL` | 投研复算与对账要求精确；浮点误差会让 `close×qty` 对不上 |
| 日期（交易日、报告期） | `DATE` | `VARCHAR`、`INT(20240101)` | 排序、区间、日历 join 依赖原生日期 |
| 事件时间 | `TIMESTAMP WITH TIME ZONE`（或引擎等价 `TIMESTAMPTZ`） | 裸 `TIMESTAMP` 不带时区声明 | 跨市场时区必须显式 |
| 摄取/更新时间 | `TIMESTAMP` + 显式时区约定 | 无默认值 | 审计与时效检查需要 |
| 证券代码 | `VARCHAR(n)`（按市场定长） | `INT`/`BIGINT`、`FLOAT` | 前导零（`000001`）、字母代码（`00700`、`AAPL`）必须按字符串存 |
| 布尔标志 | `BOOLEAN` 或 `TINYINT(1)`（引擎惯例） | `VARCHAR('Y'/'N')` 混用 | 与 `_flag` 命名配套 |
| 枚举 | `VARCHAR` + `CHECK`，或字典表 + 外键 | 裸整数 | 魔法数不可读；枚举值变化要改字典而非改表 |
| 比例/比率 | `DECIMAL(p,6)` 或 `DECIMAL(p,4)`，注释声明是百分数还是小数 | 无注释的裸数 | `0.05` 与 `5` 意思相反，注释必须写"百分数" |
| 大文本 | `TEXT`/引擎大字段类型 | 无界 `VARCHAR` | 公告正文等场景按需用，默认不进宽表 |

## 主键与唯一键

1. **每表必声明。** 主键或唯一键缺失的表无法做增量、无法去重、质检无从下手。
2. **复合键列序 = 筛选粒度顺序。** 如行情表 `(sec_code, trade_date)`，财务表 `(sec_code, end_date, ann_date)`。
3. **自然键优先于代理键。** 投研表多用自然复合键（代码+日期+来源）；确需代理键（`id`）时，仍要声明业务唯一键。
4. **分区键进入主键/唯一键。** 分区键不在键里时，唯一性检查无法裁剪分区，代价失控。
5. **唯一键列必须 NOT NULL。** 空值会绕过唯一约束，制造重复。

## 约束

- **NOT NULL**：语义必填列 `NOT NULL`；可选列允许 NULL，但注释或契约必须声明 NULL 含义——"未知"还是"不适用"。禁止"该有值却默许 NULL"。
- **CHECK**：只写有把握的业务约束，如 `amount >= 0`、`rate BETWEEN 0 AND 100`。OHLC 之间**不要**写 `high >= low` 这类约束：除权、供应商数据错误、零成交时合法数据也可能违反，约束会把脏数据挡在表外但让合法回补失败。
- **DEFAULT**：时间列用引擎标准（如 `CURRENT_TIMESTAMP`）；业务列少用默认值——默认值会掩盖缺失，质检无法区分"默认"与"真实"。供应商填充的缺省（如 `0`、`-1`）必须与业务默认区分并在注释声明。
- **外键**：投研数仓一般不用物理外键（跨库、跨引擎、性能）；关系用数据契约声明。确需物理外键时，命名见 `naming.md`。

## 单位与时区（投研硬性）

1. **单位写进注释。** 价格是元还是分、数量是股还是手、金额是元还是亿元，注释必须写；同一张表内不允许同义字段不同单位。
2. **币种显式。** 跨市场表加 `currency` 列（ISO 代码）；单市场表在表注释声明币种。
3. **时区显式。** 交易日历按 `Asia/Shanghai`；美股事件按 `America/New_York`；跨市场统一存 UTC 并在契约声明原始时区。禁止"上海时间还是 UTC 靠猜"。
4. **代码格式统一。** 同市场代码统一大小写与定长；A 股 6 位、H 股 5 位（`00700`）、美股按交易所 ticker。跨市场对比前先规格化。

## 注释

- 表注释：用途、主键、时态、更新频率、来源、市场范围。
- 列注释：口径 + 单位 + 来源 + 枚举含义 + NULL 含义；格式建议 `<口径>；单位：<单位>；来源：<来源>`。
- 注释是数据契约的一部分：`finance-data-qc` 验收时以注释为 `CONFIRMED` 口径来源之一，注释含糊 = 下游质检只能给 WATCH。

## 引擎差异提示

- MySQL：`TIMESTAMP` 有 2038 与时区陷阱，`DATETIME` 无时区；价格用 `DECIMAL`。
- PostgreSQL：`NUMERIC` = `DECIMAL`；`TIMESTAMPTZ` 存 UTC。
- ClickHouse：时间分区常用 `Date`/`DateTime`；`Decimal` 需声明精度。
- Doris/StarRocks：`DECIMALV3`；分区键须在表创建时定。
- MaxCompute：`DECIMAL(38,18)` 上限；`STRING` 存日期需注释。
- DolphinDB：`DECIMAL32/64/128`；时间类型 `DATE`/`DATETIME`/`NANOTIMESTAMP`。

不确定引擎语法时，写 DDL 前先确认方言；禁止把一种方言的 DDL 直接套到另一种引擎。
