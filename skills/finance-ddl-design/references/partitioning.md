# 分区、时态设计与兼容迁移

投研表动辄按标的×日期亿行级增长，分区与时态设计决定查询与质检能否在预算内完成；迁移方式决定存量表是否安全演进。

## 分区

1. **时间分区优先。** 投研查询几乎总是带日期范围；分区键用交易日或自然日，命名惯例 `pt`（`yyyyMMdd`）或引擎标准分区列。
2. **粒度按查询模式。** 日频行情按日分区；分钟级按日或按小时；财务按报告期或披露日（数据量小可不分）。
3. **分区键进入主键/唯一键。** 否则唯一性校验与去重无法裁剪分区。
4. **分区裁剪是生命线。** DDL 与后续查询都必须能裁剪；禁止分区键列参与隐式类型转换（`pt = '20240101'` 与 `pt = 20240101` 不能混用）。
5. **分区数量与保留期。** 与用户确认保留期与归档策略；DDL 注释写明。

## 时态设计：三列职责分离

回测与质检都依赖"当时能看到什么"，必须把三类时间分开：

| 时间 | 含义 | 命名 | 例子 |
|---|---|---|---|
| 事件时间 | 业务事实发生/归属的时间 | `*_date` / `*_ts` | `trade_date`、`end_date` |
| 可得时间 | 数据对外可见的时间（PIT） | `*_avail_ts` / `pub_ts` | `ann_date`、`publish_ts` |
| 摄取时间 | 进入本库的时间 | `ingest_ts` | 加载批次时间 |

规则：

- 事件时间与可得时间**不许合并成一列**。合并后无法回答"某日当时能看到什么"。
- 财务表至少要有 `end_date`（报告期）与 `ann_date`（公告日）两列。
- 回补、修订、更正会产生同一事件时间多版本：版本化用 `(业务键, 可得时间)` 唯一，或加 `data_version`/`source` 列，禁止覆盖历史行。
- 供应商发布时间不可得时，`*_avail_ts` 显式 `NULL` 并在契约声明，不得用 `ingest_ts` 冒充。

## 索引

1. 主键/唯一键索引由键声明生成；额外索引只加查询热点：`(sec_code, trade_date)` 是投研宽表最常见形态。
2. 避免大宽表堆索引：写放大与存储成本随索引数增长，先按真实查询模式定。
3. 分区表索引策略随引擎（全局 vs 本地/分区索引），写 DDL 前确认引擎行为。

## 兼容迁移

对已有表，默认**向后兼容**顺序：

1. **加列用 `ADD COLUMN`**，新列可空或带默认值；禁止先 DROP 再 CREATE。
2. **改口径不动旧列。** 口径变化开新列（`close_price` 与 `close_price_v2`）或新表，旧列只追加不重写；迁移脚本与设计说明记录切换点。
3. **重命名显式。** `RENAME COLUMN` + 同步更新注释与契约；禁止用"删了再加同名列"模拟重命名。
4. **删列、改类型、重建需用户单独批准**，且必须在迁移脚本里写回滚语句；执行窗口、锁行为与下游影响写入 `design.md`。
5. **版本化 DDL。** 迁移脚本按序编号（`0001_`、`0002_`），同名文件不可覆盖；已应用的版本记录到迁移表或调度元数据。
6. **回填幂等。** 回填 SQL 可重复执行且结果一致（`INSERT ... ON CONFLICT DO UPDATE` 或先删窗口再插）；回填窗口参数化，不硬编码一次性日期。

## 引擎差异提示

- MySQL：`PARTITION BY RANGE (TO_DAYS(trade_date))`；`ADD COLUMN` 在 MySQL 8 可即时。
- PostgreSQL：分区表（declarative partitioning）与 `pg_partman`；时间分区 `RANGE`。
- ClickHouse：`PARTITION BY toYYYYMM(trade_date)`；`ReplacingMergeTree` 去重依赖键。
- Doris/StarRocks：`PARTITION BY RANGE` 动态分区；`UNIQUE KEY` 模型覆盖更新。
- MaxCompute：`PARTITIONED BY (pt string)`；`INSERT OVERWRITE` 幂等回填。
- DolphinDB：`partitionedTable` 按日期分区，`TSDB` 引擎按排序键。

引擎语法不确定时先确认方言，再写 DDL。
